# 四平台自动采集与限时持续验收

版本：1.0.0rc4。Windows CLI，无前端；采集、解析、查询、报告汇编均不调用 LLM 或 OCR。

## 已跑通的实际链路

四个已配置、已核对的工作群，已经通过同一命令连续两轮运行：KIM 当前本地 SQLite → TIM 正常官方 TXT 导出 → 微信当前加密库与已提交 WAL → 企微正常单消息原生复制与三页历史。TIM、企微之间由程序点击系统任务栏中唯一的正在运行窗口按钮完成切换，不需要每轮人工切前台。查询绝不触发这些桌面操作。

这次初始验收库为 4,736 条：KIM 9、微信 62、TIM 4,657、企微 8。它们是当时已经存在的消息；重复运行新增 0。自然新到消息、事件时间到入库后的观察间隔、持续运行时长另行记录，不能拿存量数量证明新消息延迟。

| 来源 | 自动获取 | 重要限制 |
|---|---|---|
| 微信 | 显式现有密钥配置、当前加密消息分片、验证已提交 WAL、临时派生只读库 | 不发现或提取密钥；不证明服务端历史同步完整；迟到消息重扫配置窗口 |
| KIM | 精确账号、群和 session 绑定的原生 SQLite 只读窗口 | 不刷新服务端；短暂写锁与超时有界重试，身份/结构变化不自动放宽 |
| TIM | 核对群名锚点、原生消息管理器和默认文件名，选择 TXT，等待文件写完 | 严格完整历史前缀去重；截断/改写停止。客户端 UI 必须可交互 |
| 企微 | 验证群名、消息气泡、原生“多选”，每次只选择一个消息后复制；逐页向前并在下一轮回到最新 | 三页是有界窗口，不是全群完整历史。多条一起复制生成不同聚合格式，当前不使用该格式 |

源软件版本只作诊断。没有新版本白名单、降级要求或“版本号未知就拒绝”的逻辑。实际控件、图像锚点、会话绑定、原生载荷和文件一致性仍会校验；不兼容时输出具体失败代码，不静默降级为 OCR 或纯文本。

## 运行命令

真实配置及图像锚点只保存在本机受限目录，不包含在公共示例或发行包里。先按 `examples/product-sources.json` 和 `examples/wechat-live.json` 建立自己的已审核来源；实际机器上已经校准的配置可以继续使用，不必重建。

```powershell
$im = 'C:\Tools\im-hub\im-hub.exe'
$state = 'C:\Private\im-hub'
$config = Join-Path $state 'sources.local.json'

& $im config-check --config $config
& $im --home $state verify

# 下面的时间必须替换为本次明确授权的未来截止时间，必须带时区。
& $im --home $state soak --config $config `
  --until '2026-09-17T06:11:48+08:00' `
  --duration-seconds 28800 --interval 85 --allow-ui --activate-clients
```

`soak` 是当前进程中的串行轮询，不安装 Windows 服务、计划任务或公网接口。`--duration-seconds` 在 1–86,400 之间，并始终取它与 `--until` 的较早结束点。`--until` 必须是未来且距启动不超过 24 小时。默认单段 3,300 秒，适合受外部执行器时间预算限制的环境；本机 CLI 可在显式期限内运行更长时间。外部执行器也必须允许对应时长。

`--interval` 是每轮目标起始间隔；上一轮还未完成时不会重叠启动。此次机器 TIM 一轮约 17 秒、企微三页约 50 秒，故 85 秒是测试采用的间隔，不是保证的新消息延迟 SLA。数据库驱动不占桌面，但同一个 `soak` 保持串行，避免同库写者竞争。

只验证两轮可以加 `--cycles 2`；少于两轮不能伪造两轮成功。禁用 `--activate-clients` 时不会自动跨应用切换；未经 `--allow-ui` 同意的桌面源会被拒绝。`wecom-clipboard` 等需要人工复制的来源不能用于自动 `soak`，应换成已经校准的 `wecom-ui`。

## 状态、日志与停止

```powershell
# 只读，不碰 IM 客户端、不启动采集
& $im --home $state soak-status
& $im --home $state desktop-status
& $im --home $state collection-status
& $im --home $state query '迁移' --limit 50

# 主动停止本 home 的持续验收（STOP 文件不会被程序擅自删除）
New-Item -ItemType File -Path (Join-Path $state 'runtime\soak\STOP')
```

运行状态在 `runtime/soak/status.json`；每段的 `summary.json` 和 `cycles.jsonl` 按段 ID 留存。状态包含实际开始/结束、当前来源、轮次、每源状态/耗时、最近原生获取时间、暂停原因、自然新事件候选引用和整体截止时间。正常日志没有消息正文；失败子进程的内部日志可能包含本机路径，必须保持私有。

`soak-status` 中的 `running` 是最后一次记录，不独立证明进程仍活着；结合外部执行器 Job 状态确认，不凭旧状态重启第二个写者。重启同一配置和同一授权截止时间时保留最初观察基线及累计新事件计数，新的运行段另记时间。配置改动不与当前循环混用，会停止并要求重新开始。

退出码 0 要求当前段最后一轮全部来源成功、无暂停来源；4 表示轮次不完整、来源暂停、停止或其他持续验收未完成。顶层 JSON 的 `ok=true` 只说明命令生成了结构化报告，不等于全部来源成功。应同时检查 `status`、`last_cycle_all_succeeded`、`paused_sources` 和 `stop_reason`。

## 安全与恢复契约

每个 home 只有一个持续采集写者；桌面操作另有全局租约。子进程先等待父进程确认其受控生命周期，Windows 使用关闭即终止的 Job Object 管理子进程树；到期、STOP、超时和中断均回收本工具子进程，不终止原 IM 客户端。真实无害子/孙进程测试验证了生命周期回收。

每次 GUI 动作前都检查绝对截止时间、STOP、按住的键/鼠标、用户输入和前台进程。切换通过系统任务栏中的精确单窗口按钮，不修改 Windows 前台锁、不附加别的线程、不注入强制抢焦点组合键。客户端多窗口、任务栏遮挡、身份不明确就停，不猜测哪个窗口是目标。

企微的 Ctrl+C 会自动退出多选；驱动会先确认普通界面，避免点击已经变成输入区的旧关闭位置。已识别的残留多选可恢复；未知对话框不盲目关闭。窗口刚激活时滚动条可能隐藏，驱动仅用已核对消息区域内的有界正常向下滚动显露滚动条，然后验证最新位置；看不到滚动条并不代表已经到底。

短暂写锁、读取快照发生变化、活动回滚日志及 SQLite 查询超时最多有三次后续轮次重试。真实进程/会话/结构/消息身份冲突不归类为瞬时故障，不自动改配置或丢弃历史。来源批次只有导入且物理回读成功后才提交游标；失败后先恢复同一不可变批次。

RC4 对已经正常触发复制、来源身份/序列仍稳定的快照，最多用1.5秒等待同一个 OpenClipboard API 可用；不会清空剪贴板、读取历史、改权限或升权。来源变化立即拒绝，持续不可用仍明确暂停。CLI 最外层保证原生扩展异常也返回 JSON 而非空输出；未知异常不被算作成功。原始运行中捕获的错误仍保留，详见 [CLIPBOARD_RECOVERY.md](CLIPBOARD_RECOVERY.md)。

## 验收口径

必须区分：格式单测、实际后端合成测试、当前客户端自动获取、旧消息去重、自然新消息到达、持续运行时长、错误恢复、服务端完整历史。前五类不能互相替代。`full_final_acceptance` 不由一次退出码自动改成 true；总验收需要读完当前记录与缺口后单独判断。

`new_event_candidates` 只统计本次观察基线后发生、通过本次采集新写入且标为真实来源的消息；引用为 `immsg:` 消息键。时间差是消息时间戳到采集后查询时刻的观察差，不是直接测到的网络传输延迟。群在夜间没有发言时计数可以为 0，不发送消息造样本，也不将更早历史记录算作新事件。

UI 适配是本机已核对的亮色布局、图像锚点和任务栏行为。换 DPI、主题、多个客户端实例、锁屏或窗口结构改变时可能需要重新校准；这属于实际能力变化，不是按软件版本拒绝。当前对附件和未知消息类型保留缺口；撤回/编辑发生身份内容冲突时停止，不宣称已实现完整编辑版本语义。
