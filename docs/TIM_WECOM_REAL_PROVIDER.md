# TIM / 企微：真实目录能力核验与逐会话采集接线

## 实机观察与候选纠偏

2026-09-17 在当前运行的 Windows 客户端上进行了只读窗口和原生 UIA 核验。TIM 观察版本为 3.5.1.22171，企微为 5.0.11.6018；这只是此次遥测，不是支持版本白名单。

TIM 的会话列表位于较深的 UIA 树，能够读取 ListItem 的显示名；当前可见页观察到 13 个条目，其中 12 个完整显示，含一个“群助手”入口和一条部分显示条目。它们不是 13 个已验证活跃会话，更不是全账号分母。“群助手”里显示有新消息的群数不能当作全部折叠群数。此次未展开群助手子目录。

当前 TIM 会话行未提供候选要求的原生会话 ID、绝对最后活动时间和独立目录总计数；会话列表不提供 ScrollPattern。企微仅暴露外层窗口及两个外层控件，未暴露所需目录字段。因此，之前的严格 UIA 元数据候选不能通过填入虚构选择器在这些客户端上宣布兼容。真实客户端适配门仍未通过。

工具层 TIM 的可复用 UIA 元素句柄返回 runtime-ID 长度错误；本地只读观察绕开的是该句柄编码限制，不是访问控制，且没有把 RuntimeId 用作会话身份。窗口截图桥接曾返回无效 JSON，有限本地 PrintWindow 观察用于核对界面；截图和带真实名称的证据均仅存 `.local/`，不进入仓库。

## 新增只读探针

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m im_hub probe-desktop-directory --platform qq
.\.venv\Scripts\python.exe -B -X utf8 -m im_hub probe-desktop-directory --platform wecom
```

命令不要求初始化消息 home，不切换窗口、不滚动/展开/点击、不获取消息预览、不复制、不写库或清单，也不调用模型。它对两个连续可见页观察作一致性检查；变化返回明确错误，不悄悄拼接两个布局。输出名称只是临时定位线索，同名条目不合并，群助手另列。`inventory_ready=false`、原生 ID/绝对时间为空、完整性为 false；企微无法枚举时数量是 null，而不是 0。

现有普通 `query`、`week-status`、`desktop-backfill-plan` 不会触发这个探针或读取客户端。

## 新增逐会话采集再回补命令

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m im_hub --home '.local\reviewed-state' collect-desktop-week `
  --inventory '<已核验的固定窗口清单ID>' --config '.local\reviewed-sources.local.json' `
  --max-conversations 1 --offset 0
```

这条命令填补“已经确定会话身份和采集配置，但尚无 pinned capture”到“按固定窗口物理回补”的接线。它不能把上面的显示名探针结果升级成身份清单，也不是自动扫描陌生账号或猜测会话的功能。

输入仍为 `im-hub-active-accounts/1` 生成的不可变固定窗口清单及 `version=1` 来源配置。来源必须同时匹配平台、账号命名空间、source_epoch、data_class、会话 ID、名称，以及显式的 `directory_binding` 原生 ID/类型映射。缺失或多个匹配均 HOLD；单聊和未知类型不走旧群聊适配器。

来源可以是已核验的 TIM 官方 TXT 文件采集（`tim-export`）或已审核的 `tim-ui` / `wecom-ui`。UI 额外需要 `--allow-ui` 和由用户明确提供、仍有效的 `IM_HUB_DESKTOP_UNTIL`；既有前台/账号/剪贴板/输入中断/STOP 检查不变。不设置默认授权时长、不自动续期旧授权、不强行切换前台。实际本轮没有运行该命令去操作真实聊天软件。

首次获取成功后立即绑定返回的确切 run ID，再调用已有固定窗口回补逻辑。来源 profile 的指纹不包含路由字段，旧账号和严格 TIM 全历史前缀身份不被重绑。每次最多 20 个候选、默认 1 个；按返回的 offset 接续，不新建定时器。

## 固定窗口不再先导入范围外消息

原桌面采集函数新增可选 `import_window`，由上述明确采集命令传入清单窗口；普通旧 `collect` 调用行为不变。它为该次 run 记录 since/until 并在首次入库时就使用 `[since, until)`，而不是先全量导入再截取。TIM 的原始官方导出仍完整保留以验证严格前缀与同秒消息序号；筛选不修改原始证据。

待恢复的 run 必须与本次所请求窗口完全相同，否则拒绝恢复到不同窗口。观察时间早于窗口末端的旧捕获不能假装覆盖该窗口。`history_complete=false` 始终保留；窗口内已捕获记录读回通过不等于客户端/服务器所有历史完整。

## 断线与未知结果

采集前在同一 inventory 下写入不可变 `acquire/<entry-key>/intent.json`，绑定清单哈希、来源指纹、窗口和条目。采集返回后保存确切 run ID 相关记录，再生成 pinned binding 并入库读回。

重试有成功相关记录时只复用该 run，不再次驱动 UI。已有 intent 但没有可核实结果时，返回 `reconciliation_required`；不能因超时、断线、配置编辑或重新启动而选择“最新 run”或再次发起采集。操作者核对原采集的真实完成结果并明确提供 `captured_run_id` 后可复用；若原底层导入仍失败，须先恢复并核实该原 run。这一边界是安全暂停，不是自动恢复成功。

所有步骤验证同一清单/配置哈希；来源发生变化时保留已产生的底层证据，但不签发不相符的完成回执。消息去重、ChatLab 校验与物理回读仍由原模块承担，不建立第二份业务事实账本。

恢复复核进一步修复两个跨步骤边界：原始采集配置的哈希检查现在会传入嵌套回补，在物理读回之后、写入任何回执之前再次校验；不能因为中间生成了不可变的 pinned 配置而丢失原请求约束。若原配置变化，保留已有底层批次与原回执，不向新请求签发完成结果。

`collect-desktop-week` 的 `retry_offsets` 明确列出本页尚未完成的条目。遇采集结果未知或需要核对时停止，`next_offset` 留在该条目而非跳到下一会话；重复调用只返回核对要求，不会重新驱动 UI。其他缺绑定或单聊未支持的 HOLD 可以继续扫描，但仍留在 `retry_offsets`，不能把扫描位置当作完成水位。

## 恢复复核验收

2026-09-17 的恢复复核版本已通过 405 项全量测试及 13 项真实 ChatLab 0.37.1 后端合成验证，均无失败、错误和跳过，两组验证绑定同一最终 Python 源码快照。旧微信/KIM 固定窗口的 102 个会话、2,594 条消息读回通过，1,406 个私有文件 SHA-256 前后一致。恢复复核回执见 `ACCEPTANCE_TIM_WECOM_RECOVERY.json`；较早的 `ACCEPTANCE_TIM_WECOM_REAL_PROVIDER.json` 保留原 400/8 验证及当时的实机观察，不将历史报告覆盖成新结果。

本次最新只读探针依旧只能看到 TIM 当前页的 13 个条目（含一个群助手入口、一个非完整可见条目），企微的目录条目数为未知。没有展开普通/折叠入口，没有新增真实消息或续期旧桌面独占授权。合成数据运行真实后端，不等于真实聊天客户端采集通过。

## 当前仍需完成

真正展开 TIM 群助手及企微普通/折叠入口，需要新的可独占桌面窗口与可工作的实际输入/控件路线。实机元数据不暴露时应基于真实界面逐项核验可用原生导出/复制路径，而非伪造身份或放松校验。单聊适配、新会话真实采集、全目录独立分母和同窗口逐会话回补仍需各自证据。本轮的只读实机探针与代码测试不等于这些门已通过。
