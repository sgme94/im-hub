# 施工计划

## 已落地：独立 CLI 基线

- [x] 独立 `im-hub` Python 包、console entry point、`python -m im_hub`。
- [x] 无前端、无必需 LLM、无发送入口。
- [x] 微信/KIM JSONL、TIM TXT、企微原生/JSON、QCE JSON 的本地适配。
- [x] ChatLab 固定版本依赖路径可配置，解析器不依赖旧实验目录。
- [x] 配置式完成文件 + 来源 manifest 的 `collect`；原始 hash/观察时间核对。
- [x] 单写者入库、回读核对、失败对账、只读查询/分页/覆盖。
- [x] 旧库只读兼容、证据导出、规则初筛、候选引用检查。

## P1：真实新增数据采集

- [x] KIM 原生 SQLite：明确账号目录和群/session 绑定、短只读事务、WAL 读取、重叠窗口、失败不前移及待恢复批次对账。
- [x] 微信已有明文 SQLite 分片：受控只读、跨分片身份、整个配置窗口重扫；缓存上游时效标记 unknown，不访问密钥。
- [x] `collection-status`、`--dry-run`、`--reconcile`，支持空窗口、schema/来源身份变化停止和跨进程重放。
- [ ] 微信加密客户端的安全实时刷新桥、源客户端/数据库重建后的重新绑定与完整回补流程。当前不调用会自动提取密钥的旧读取器初始化。
- [ ] TIM：确定性 UI 导出状态机，三重会话核对，文件完成检测，用户输入即暂停；跨次导出身份另行验证，不能仅用正文 hash 去重。
- [ ] 企微：正常消息选择/复制自动化、剪贴板新序列和来源版本验证、逐页覆盖、未知元素保留、跨群绑定及恢复。
- [x] 本次两个数据库驱动提供读取观察、成功/失败批次、本地扫描边界和正文缺口，不把扫描边界称为服务端完整水位。
- [ ] TIM/企微桌面驱动实现后采用相同的覆盖与恢复契约。

## P2：稳定性与分析接入

- [ ] 连续 24–72 小时只读试运行、客户端/采集器重启、离线恢复、版本变化暂停、备份还原。
- [ ] 语义分析为可选外部消费者；原文是数据不是指令，最小授权证据出站。
- [ ] 复用既有 MyMind 处理器，不建立第二份项目状态账本，不直接改 completed。
- [ ] 大规模查询性能、撤回/编辑版本语义、附件原文解析和消息上下文关联。

v0.3.0 仍不启用周期任务、不创建公网服务、不新登录账号、不操作聊天界面。数据库驱动的合成、实际后端和真实来源验收分开记录；客户端重启、无人值守和完整历史不能由这些测试推定完成。
