## P1：真实新增数据采集

- [x] KIM 原生 SQLite：明确账号目录和群/session 绑定、短只读事务、WAL 读取、重叠窗口、失败不前移及待恢复批次对账。
- [x] 微信已有明文 SQLite 分片：受控只读、跨分片身份、整个配置窗口重扫；缓存上游时效标记 unknown，不访问密钥。
- [x] `collection-status`、`--dry-run`、`--reconcile`，支持空窗口、schema/来源身份变化停止和跨进程重放。
- [x] 微信当前加密库/WAL只读桥：只使用现有密钥配置，逐页认证，三轮真实读取通过；不调用密钥提取或旧读取器构造函数。
- [ ] 数据源重建后的完整回补、自然新到消息持续延迟观察。
- [x] TIM：本机图像锚点/原生对话框自动导出实测通过；跨次文件采用严格前缀而非正文 hash 合并。
- [x] 移除源客户端版本白名单；版本缺失/变化不拦截，保留实际身份/格式/控件校验。
- [x] 企微：实际自动定位、单条原生复制、三页历史和回到最新通过；图像只定位控件，不读取正文。
- [x] 明确截止时间下通过系统任务栏正常切换 TIM/企微，已连续两轮实测，无每轮人工切前台。
- [x] `soak` 单写者、受控子进程树、到期/STOP/输入检测、配置快照、短暂锁/快照变动有界重试。
- [x] 本次两个数据库驱动提供读取观察、成功/失败批次、本地扫描边界和正文缺口，不把扫描边界称为服务端完整水位。
- [x] TIM/企微使用统一来源批次和回读提交契约，重复记录不推进错误水位。

## P2：稳定性与分析接入

- [ ] 按本次用户授权截止时间完成持续运行观察；24–72 小时属于另行授权的扩展测试。
- [x] 实际无害子/孙进程测试验证父进程持有的 Job 关闭即回收，客户端原进程不终止。
- [ ] 客户端断线/重建与复杂 UI 中断状态的进一步实机覆盖；不猜测未观测的恢复结果。
- [ ] 语义分析为可选外部消费者；原文是数据不是指令，最小授权证据出站。
- [ ] 复用既有 MyMind 处理器，不建立第二份项目状态账本，不直接改 completed。
- [ ] 大规模查询性能、撤回/编辑版本语义、附件原文解析和消息上下文关联。

RC 不启用周期任务、不创建公网服务、不新登录账号。数据库、离线真实样本、实际后端合成验证和真实桌面验收分别记录；打包成功、合成通过都不代替未完成的当前版本客户端验收。
