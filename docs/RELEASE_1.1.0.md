# im-hub 1.1.0 — TIM / KIM / 微信三平台稳定版

发布日期：2026-09-18。

## 稳定边界

本版本正式稳定边界只包含 **TIM/QQ、KIM/OA、微信**。企业微信代码与历史验证继续保留为实验候选，但不计入 1.1.0 稳定验收，不因安装本版本自动启用，也不用于声明三平台以外的完整性。

- TIM：官方 TXT 完整导出、精确会话绑定、严格前缀追加校验、固定窗口导入、物理读回与重放去重。真实普通列表及群助手/折叠入口已有逐群身份核验和导出证据；仍不声明整个账号所有会话已经完成独立分母核验。
- KIM/OA：精确绑定账号目录、session/group/user/message 原生 SQLite，只读快照、固定窗口、群聊/单聊分类和回补。
- 微信：当前加密数据库及已提交 WAL（只使用显式既有密钥配置），账号级最近七天会话发现、群聊/单聊分类、固定窗口回补；富媒体/附件缺口单列。
- 企业微信：experimental / HOLD，不属于稳定边界。

## 真实验收基线

最近一次账号级固定窗口验收中，微信 89 个可回补会话（54 群、35 单聊）共 2,502 条，KIM 13 个会话（5 群、8 单聊）共 92 条，全部物理读回通过，重放新增 0。

TIM 的最新实机验收已在普通列表和“群助手”折叠入口中完成 4 个群聊的原生身份核实、官方完整导出和同一固定窗口回补；窗口内 189 条全部物理读回通过，重放新增 0。这里证明的是 TIM 受控逐会话链路成熟，不把 4 个群或显示名分页数量冒充全账号完整分母。

## 数据与 MyMind 边界

im-hub 是采集/证据层，不拥有业务项目状态。查询不会触发采集。1.1.0 交付给 MyMind Collect 的只是不可变来源批次、来源身份、固定窗口、消息证据与逐平台/逐会话覆盖；后续 Analyze/Reuse 才能根据既有治理生成候选事实，正式状态仍只能进入 MyMind 唯一的 `Logs/WorkEvents` 事实账本。

不创建第二事实账本、第二知识系统或长期调度器。

## 发布产物

- Python wheel / sdist：用于已有 Python 3.11+ 环境。
- Windows x64 portable：自带固定 ChatLab CLI 0.37.1、Node 22.22.2 及许可证，核心运行不需要 LLM。
- 便携包未做代码签名；必须核对 SHA-256。

发布产物不得包含真实聊天内容、截图、账户标识、密钥或本机私有配置。
